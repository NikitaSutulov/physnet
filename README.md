# PhysNet

Система віддаленого адміністрування SDN-мережі з візуалізацією на планах
приміщень. Пристрої, які бачить контролер ONOS, розміщуються на кресленнях
поверхів, кабелі прокладаються вздовж стін, а зміни стану мережі приходять у
браузер у реальному часі. Політики маршрутизації застосовуються в ONOS як
intents.

## Можливості

- **Плани приміщень.** Завантаження креслень (PNG, JPEG, WebP, SVG) у сховище
  Garage, групування за будівлями й поверхами, перемикач поверхів зі
  збереженням камери, мінікарта.
- **Інтерактивне полотно (react-konva).**
  - масштабування колесом миші навколо курсора, панорамування;
  - перетягування пристроїв з панелі нерозміщених, поворот, прив'язка до сітки;
  - кабелі з точками зламу.
- **Синхронізація з ONOS.** Комутатори, порти, хости й лінки опитуються кожні
  5 с. Зміни (аварія лінії, пристрій недоступний тощо) стають подіями в
  журналі.
- **Реальний час.** Socket.IO: переміщення й нові кабелі видно в усіх
  відкритих вкладках, статуси оновлюються без перезавантаження.
- **Дашборд.** Лічильники пристроїв, портів і лінків, стан контролера, стрічка
  подій, каталог планів.
- **Політики маршрутизації.**
  - типи intent «Хост ↔ хост» і «Порт → порт» з фільтром трафіку (IP-адреси й
    підмережі, протокол, порт призначення);
  - застосування й відкликання;
  - живий стан intent в ONOS.
- **Керування портами.** Увімкнення й вимкнення портів комутаторів через ONOS.
- **Доступ.** JWT-автентифікація; ролі `ADMIN` (усе) та `OPERATOR` (перегляд).

## Стек

| Частина        | Технології                                                                   |
| -------------- | ---------------------------------------------------------------------------- |
| Бекенд         | NestJS 12, Prisma 7 (PostgreSQL 16), Socket.IO, `@nestjs/schedule`, Swagger  |
| Фронтенд       | Next.js 16 (App Router), React 19, react-konva, TanStack Query, Zustand, Zod |
| Інфраструктура | Docker Compose: PostgreSQL, Garage (S3), Garage WebUI                        |
| SDN            | ONOS (зовнішній), Mininet для демонстраційної мережі                         |

Структура монорепозиторію (pnpm workspaces):

```
apps/api         NestJS: REST API, вебсокет-шлюз, синхронізація з ONOS
apps/web         Next.js: вебінтерфейс
packages/shared  спільні TypeScript-типи запитів, відповідей і подій
docker/          конфігурація Garage
mininet/         демонстраційна топологія для Mininet
```

## Запуск

### Вимоги

- Node.js 24+, pnpm 10 (`corepack enable`)
- Docker із Docker Compose
- ONOS, доступний бекенду (REST, порт 8181) і Mininet (OpenFlow, порт 6653)

### Кроки

1. **Залежності.**
   ```bash
   pnpm install
   ```
2. **Змінні середовища.**
   ```bash
   cp .env.example .env
   cp apps/api/.env.example apps/api/.env
   cp apps/web/.env.example apps/web/.env.local
   ```
   У кореневому `.env` згенеруйте `GARAGE_RPC_SECRET` і `GARAGE_ADMIN_TOKEN`
   (`openssl rand -hex 32`). В `apps/api/.env` задайте `JWT_SECRET` (теж
   `openssl rand -hex 32`) і параметри ONOS (`ONOS_URL`, `ONOS_USER`,
   `ONOS_PASSWORD`).
3. **Інфраструктура.**
   ```bash
   pnpm infra:up
   pnpm infra:garage:init
   ```
   Скрипт ініціалізації Garage виводить ключ доступу. Перенесіть `Key ID` і
   `Secret key` у `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` в
   `apps/api/.env`.
4. **База даних.** Генерація клієнта Prisma, міграції й перший
   адміністратор (`SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`, типово
   `admin@physnet.local` / `changeme123`):
   ```bash
   pnpm db:generate
   pnpm db:migrate
   pnpm db:seed
   ```
5. **Запуск.**
   ```bash
   pnpm dev
   ```
   Запускає API і вебінтерфейс разом; `Ctrl+C` зупиняє обидва.

| Адреса                                      | Що там                     |
| ------------------------------------------- | -------------------------- |
| http://localhost:3000                       | вебінтерфейс               |
| http://localhost:3001/api                   | REST API                   |
| http://localhost:3001/api/docs              | документація API (Swagger) |
| http://localhost:3001/api/docs/openapi.json | специфікація OpenAPI       |
| http://localhost:3909                       | Garage WebUI               |

### ONOS

Подійде будь-який інстанс ONOS 2.x з активними застосунками
`org.onosproject.openflow`, `org.onosproject.hostprovider` і
`org.onosproject.fwd`. Наприклад, у Docker:

```bash
docker run -d --name onos -p 8181:8181 -p 6653:6653 \
  -e ONOS_APPS=drivers,openflow,hostprovider,lldpprovider,fwd,proxyarp \
  onosproject/onos:2.7.0
```

Застосунок `org.onosproject.physnet`, якому належать intents політик, бекенд
реєструє сам перед першим застосуванням політики.

## Демонстраційна мережа

[mininet/physnet_demo.py](mininet/physnet_demo.py) будує невеликий
двоповерховий кампус:

- ядро в серверній з двома серверами;
- по комутатору розподілу на поверх, з'єднаних з ядром у кільце;
- чотири комутатори доступу і шість хостів.

```bash
sudo python3 mininet/physnet_demo.py
```

Без параметрів скрипт підключається до ONOS на тій самій машині
(`127.0.0.1`, порти 6653 і 8181). Якщо ONOS працює на іншій машині або у
віртуальній машині, додайте `--controller <адреса ONOS>`.

Скрипт:

- вмикає реактивну пересилку ONOS;
- запускає вебсервер на `srv1` (10.0.0.100:80);
- робить так, щоб ONOS дізнався про всі хости.

У консолі Mininet з'являються додаткові команди:

| Команда    | Дія                                                                   |
| ---------- | --------------------------------------------------------------------- |
| `scenario` | покроковий сценарій демонстрації всіх можливостей                     |
| `fwd off`  | вимкнути пересилку «усі з усіма»: проходить лише трафік за політиками |
| `fwd on`   | повернути звичайну пересилку                                          |
| `discover` | нагадати ONOS про всі хости (після вимкнення порту тощо)              |
| `intents`  | intents в ONOS та їхній стан                                          |

Що можна показати:

- **Аварія і відновлення.** `link s2 s3 down/up`, `switch s7 stop/start`.
- **Вимкнення порту з інтерфейсу.** Пінг, що йде через порт, зупиняється.
- **Політики при `fwd off`:**
  - «Хост ↔ хост» відкриває зв'язок між двома хостами, і тільки між ними;
  - встановлений intent переживає обрив кільця: ONOS прокладає шлях через ядро;
  - «Порт → порт» із фільтром пропускає до `srv1` лише HTTP, а `ping` не
    проходить.

Перед демонстрацією видаліть недоступні пристрої старої топології на сторінці
«Пристрої» (кнопка очищення неактивних).

## Тести

- **Unit-тести (Vitest).**
  - API: перетворення даних ONOS, побудова intents, черга синхронізації тощо.
  - Вебінтерфейс: геометрія полотна, форма політики, обробка подій реального
    часу.
- **E2e-тести** працюють зі справжнім HTTP-сервером і вебсокетами проти
  підробленого ONOS.
  - Потрібні тільки контейнери (`pnpm infra:up`).
  - Окрема база `physnet_test` створюється, мігрується й наповнюється
    автоматично, тож робочі дані тести не чіпають. Іншу базу можна задати в
    `TEST_DATABASE_URL`.

Pre-commit хук (husky) запускає prettier, перевірку типів і лінтер.

## Обмеження

- **Затримка до 5 с.** ONOS опитується через REST кожні `ONOS_POLL_INTERVAL_MS`
  (типово 5 с), тож зміни в мережі доходять до інтерфейсу з такою затримкою.
- **Журнал подій** зберігається в пам'яті бекенду: останні 100 подій до
  перезапуску.
- **Intents не змінюються на місці.** Застосовану політику треба відкликати
  перед редагуванням.
